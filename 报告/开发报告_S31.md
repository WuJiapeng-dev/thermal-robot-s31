### 2.4 编译过程中真实踩到并已修掉的 6 个问题

按出现顺序，全部是本机真实报错，不是预判：

1. **组件管理器联网失败**
   `ERROR: Cannot establish a connection to the component registry (components-file.espressif.com/.../esp_codec_dev.json)`
   原因：工程没有 `dependencies.lock`，CM 试图联网解析。
   处理：从本机 xiaozhi 工程缓存复制完整的 `espressif__usb`、`espressif__esp_codec_dev` 到 `managed_components\`，根 `CMakeLists.txt` 加
   `set(EXTRA_COMPONENT_DIRS "${CMAKE_CURRENT_LIST_DIR}/managed_components")`，构建时 `IDF_COMPONENT_MANAGER=0`。**没有改系统环境、没有装包。**

2. **`Failed to resolve component 'json'`**
   ESP-IDF v6.1 无名为 `json` 的组件。
   处理：`main/CMakeLists.txt` 去掉该依赖；`app_link.c` 从 cJSON 改写为手写 JSON 拼接（固定字段、定长缓冲、长度检查）。

3. **`app_storage.c`：`SDMMC_HOST_DEFAULT` / `sdmmc_slot_config_t` / `SDMMC_SLOT_NO_CD` 全部未声明**
   原因：v6.1 里 `esp_vfs_fat.h` 不再顺带引入 legacy SDMMC 头，本文件只 include 了 `sdmmc_cmd.h`。
   处理：加 `#include "driver/sdmmc_host.h"` 与 `#include "sd_protocol_defs.h"`；`SDMMC_OCR_SDHC` 宏在 v6.1 已改为 `SD_OCR_SDHC_CAP`，同步替换。
   附带确认：`SDMMC_HOST_DEFAULT()` 在 ESP32-S31 上的默认 slot 就是 `SLOT_0`，`SDMMC_SLOT_CONFIG_DEFAULT()` 的默认脚正是 24/25/20~23，与引脚表一致。

4. **`app_audio.c`：4 处 `discards 'const' qualifier`（v6.1 把这类 warning 升级为 error）**
   `audio_codec_new_i2s_data` / `audio_codec_new_i2c_ctrl` / `esp_codec_dev_new` / `esp_codec_dev_open` 形参都不是 const。
   处理：4 个配置结构体去掉 `const`（`i2s_cfg`、`i2c_cfg`、`device_cfg`、`sample_info`），语义不变。

5. **`app_console.c`：`esp_console_init` 参数个数不对**
   v6.1 签名是 `esp_console_init(const esp_console_config_t *)`。
   处理：补 `esp_console_config_t{max_cmdline_length=128, max_cmdline_args=8}`。

同时清掉了 `app_cloud.c` 两个 `unused` warning（WiFi 关闭时把静态变量与事件回调整体包进 `#if APP_WIFI_ENABLE`）。最终一轮**0 warning**。

6. **NAN 被序列化成非法 JSON（15:47 补修，编译期不报错、属协议缺陷）**
   `hotspot->temp_c` 取自 `raw_to_celsius()`，恒为 `NAN`；newlib 的 `snprintf("%.1f", NAN)` 输出字符串 `nan`，拼出来是 `"t":nan`，**不是合法 JSON**，对端 `parse_number()` 会解析失败并把 `t` 标为缺失。
   处理：`app_link.c` 引入 `temp_out`，用「与 NAN 的任何比较都为 false」把无效值兜到哨兵 `-273.0`；`main.c` 的热点日志改为先格式化到 `temp_text[]`，无效时打印 `--`，避免日志出现 `temp=nan` 误导排查。
   复编结果：`Project build complete`，0 error / 0 warning，bin 551,280 B（+80 B）。

## 六、不确定项清单（10 条，均需实测）

### 6.1 `HOTSPOT_RAW_DELTA = 1500` 是待标定估计值
- **不确定什么**：这个 raw counts 差值到底对应多少温度，没有任何标定依据，只是「能把明显热点挑出来」的初值。
- **影响什么**：漏报（阈值偏高）或误报（偏低）；所有热点判定的正确性都挂在这个数上。
- **怎么验证**：黑体或稳定热源（如恒温烙铁头、加热台）在固定距离下采集，记录同一目标在不同温度下的 raw 中位数与峰值差，拟合出 delta→ΔT 曲线后回填。

### 6.2 `raw_to_celsius()` 一律返回 NAN，温度字段恒为 -273.0
- **不确定什么**：raw→℃ 需要 FFC + 列 FPN + 工厂 NUC（按 FPA 温度选 gate）+ Planck 反演，本轮**没有**任何一环的可信参数。
- **影响什么**：STM32 端温度永远显示「--」；`conf` 只反映 raw 相对强度，不是温度置信度。
- **怎么验证**：拿到黑体 + 原厂 SDK 或标定文件（`mag_cali.bin` 已能下载到 PSRAM），先验证 NUC 输出与黑体读数偏差，再填 `raw_to_celsius()`。

### 6.3 `mag_cali.bin` 的下载路径与长度校验未与实物对过
- **不确定什么**：`GetCaliInfo`/`GetCaliFile` 命令字（0x6BB6B66F / 0x6BB6B670）来自公开逆向资料；EP `0x84` 的实际分包节奏、1.8MB 是否一次下完、128B 头字段含义都未验证。
- **影响什么**：下载可能中途超时或长度对不上，`app_thermal_download_calibration()` 返回错误；不影响扫码主流程（仅打日志）。
- **怎么验证**：接实物跑 `usb_probe` 看端点，再单步打印每次 `0x84` 传输长度与累计量，与 1,843,328 B（128 + 48×38,400）比对。

### 6.4 SYN6288 的 GB2312 字库只覆盖约 70 个字
- **不确定什么**：`app_tts.c` 内置的是「界面/播报高频字」的手工映射表，不在这张表里的汉字会被记日志后**跳过**，播报会出现缺字；波特率 9600 也是默认值。
- **影响什么**：标定表里的 `zh_name` 只要含生僻字，播报就不完整。
- **怎么验证**：拿实物模块，先用 `tts_test`（播「测试一二三」）确认波特率与帧格式；再把 `calib.csv` 里实际用到的区域名全量跑一遍，把缺的字补进映射表。

### 6.5 ES8311 采样参数（24kHz / 16bit / 单声道 / 输入增益 30dB）
- **不确定什么**：`AUDIO_SAMPLE_RATE_HZ=24000`、`AUDIO_MIC_GAIN_DB=30.0f` 是按板卡常规值给的，未实测信噪比与是否削顶。
- **影响什么**：`audio_test` 的峰值读数可能偏低或饱和；本轮不做语音识别，所以只影响自检结论。
- **怎么验证**：跑 `audio_test` 看 1 秒峰值是否落在满量程 30%~70%；偏离就调增益或采样率。

### 6.6 GPIO46 作 USART2 TX 是 strapping 脚（ROM 日志选择）
- **不确定什么**：上电瞬间该脚电平是否会影响启动模式/日志输出。
- **影响什么**：极端情况下上电启动异常或 ROM 日志跑到别处。
- **怎么验证**：上电抓 GPIO46 电平与串口首包；若异常，只改 `bsp_pinmap.h` 里 `PINMAP_LINK_UART_TX` 一个宏换脚（代码已按此设计）。

### 6.7 OV2640 只做到「通信探测」，未取图
- **不确定什么**：`esp32-camera` 组件是否已支持 `esp32s31`（本轮**没有**引入，因为无法确认）；20MHz XCLK 对该模组是否合适（部分模组要 24MHz）。
- **影响什么**：现在只能拿到「SCCB 有无应答 + PID/VER」，没有可见光图像，也没有图像与热像的配准。
- **怎么验证**：跑 `cam_test` 看 PID 是否为 `0x26`；再单独查 `espressif/esp32-camera` 的 `idf_component.yml` targets 是否含 esp32s31，确认后再引入。

### 6.8 USB 传输参数（4096B/包 × 2 传输、ACK 缓冲 4096B）
- **不确定什么**：Full-Speed bulk 实际 `wMaxPacketSize` 是否为 64；一次提交 4096B（64 包）在该设备上的稳定性；`0x82` ACK 的真实长度是否可能超过 4096B。
- **影响什么**：可能出现 `ESP_ERR_TIMEOUT` 或短包导致的切帧错位。
- **怎么验证**：`usb_probe` 打印端点描述符；`thermal_test` 打印 10 帧的帧率、帧计数连续性、丢弃帧数，若丢弃率 >1% 就先降 `THERMAL_USB_CHUNK_BYTES` 到 1024 复测。

### 6.9 外购 INMP441 的备用宏与已用引脚冲突
- **不确定什么**：`PINMAP_EXT_MIC_BCLK=35`、`WS=36`、`DIN=37` 与 OV2640 D6/D7、链路 RX 是同一批脚。
- **影响什么**：一旦把 `AUDIO_USE_EXTERNAL_I2S_MIC` 改成 1，摄像头与串口链路会同时失效，而且不会有编译错误。
- **怎么验证**：本轮保持 0（不接外购麦）。将来要接，先在 `bsp_pinmap.h` 里把三个宏改到空脚，再改开关。

### 6.10 标定表 `calib.csv` 尚未存在
- **不确定什么**：没有任何真实 `calib.csv` 样本，解析器只按 `group_id,zh_name,x0,y0,x1,y1` 六字段实现，字段顺序、是否带表头、坐标是左上/右下还是中心+宽高，都未与实物对齐。
- **影响什么**：表缺失时全部热点落到 `UNKNOWN / 未知区域`（已按提示词降级，不阻止启动）。
- **怎么验证**：先手写一份含 3 条记录的 csv 放 `/sdcard/calib.csv`，跑 `calib_test` 看条目数与坐标命中是否符合预期。
