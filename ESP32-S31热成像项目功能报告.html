1一页速览 / 核心结论

一句话概括：这是一个跑在 ESP32-S31 上的热成像热点巡检机器人主控程序——通过 USB Host 读取 MAG160Core 热成像模组的 160×120 原始帧，用相对阈值算法在画面里找出发热区域，按坐标查 SD 卡上的区域表得到中文名，然后同时走三路输出：串口发 JSON 给 STM32、SYN6288 语音播报、SD 卡存快照；WiFi 云端为默认关闭的可选项。

核心结论（先看这 6 条）

  1. 功能主线已打通为本地闭环。采集 → 热点分析 → 区域查表 → 串口/语音/存储输出，全链路在 main.c:run_scan() 中有明确调用，可独立运行，不依赖网络。
  2. 温度值目前不可用。raw_to_celsius() 明确返回 NAN（app_thermal.c:703-712）；代码注释反复强调"不得把 raw count 当摄氏度上报"。所谓"温度"在 JSON 里是哨兵值 -273.0，语音则播报"温度未标定"。
  3. 热点判据是相对量，不是绝对温度。阈值 HOTSPOT_RAW_DELTA=1500 是"相对全图中位数的原始计数差"，注释注明为估算值，等待黑体/现场标定，不是 8℃ 的换算（app_config.h:8-10）。
  4. NUC（非均匀性校正）明确不在范围内。main.c:157 注释："NUC computation is deliberately out of scope"，只做了标定的下载与存储。
  5. 多路外设处于"已接线/已初始化但未参与主业务"状态。OV2640 仅做 SCCB 探测（plan B，无图像采集）；板载 ES8311 音频仅初始化与自检；RGB LED / BOOT 按键保留未驱动。
  6. 云端是 opt-in。APP_WIFI_ENABLE=0 且 SSID/URL 为空，空凭据绝不触发联网（app_config.h:102-107、app_cloud.c）。

6模块逐项详解

6.1 app_thermal · 热成像 USB 采集 app_thermal.c / .h

  • 设备识别：枚举 USB 设备，匹配 VID 0x833C + PID 0x0001/0x0002，查找必须的 3 个批量端点（CMD OUT 0x03、ACK IN 0x82、IMAGE IN 0x81），标定端点 CALIB IN 0x84 / OUT 0x05。
  • 帧格式：每帧 = 28 B 头 + 160×120×2 B 像素 + 28 B 尾；头 magic 0x1BB1B11B、尾 magic 0x1BB1B11C，头尾 frame_id 必须一致，否则丢弃/失败计数。
  • 解析状态机：parse_image_bytes() 用滑动缓冲查找头 magic、校验尾 magic、处理跨包拆分的 magic，坏帧逐字节滑动重同步。
  • 双缓冲 + 队列：两个 PSRAM 帧缓冲 + slot 元数据 + 长度 1 的 queue（xQueueOverwrite），新帧覆盖旧帧；thermal_get_frame() 阻塞取帧，app_thermal_get_latest() 取最新。
  • 命令事务：command_transaction() 用互斥锁串行化"下发命令 → 等 ACK"，命令含 GET_PARAMETER_1/2、GET_CALI_INFO、SET_SHUTTER、START/STOP_IMAGE；各自有超时。
  • 掉线重连：独立 task 每 500 ms 扫描设备，DEV_GONE 时关闭设备、等待 5 s 重连；连续失败 5 次拉长重试。
  • 标定下载：暂停图像流 → GET_CALI_INFO 读长度 → 分块从 CALIB IN 下载（单块 ≤65472 B，超时 60 s）→ 存 PSRAM（容量 2 MB）→ 恢复图像流。只下载存储，不做 NUC 计算。
  • 自检：app_thermal_self_test() 采 10 个不同帧，算 fps、帧号连续性、中心 raw 值。
关键口径：raw_to_celsius() 直接返回 NAN 并打警告："uncalibrated… do not report raw counts as Celsius"。这是全工程温度链路的边界，务必保留。

6.2 app_hotspot · 热点检测 app_hotspot.c / .h

详见 第 7 节。核心：全图中位数 → 相对阈值 → 4 邻域泛洪找连通域 → 面积过滤 → 跨帧位置匹配确认 → 置信度评分 → 输出 ≤8 个热点，温度字段来自未标定的 raw_to_celsius()。

6.3 app_calib · 区域查表 app_calib.c / .h

  • 从 /sdcard/calib.csv 解析 组名,中文名,x0,y0,x1,y1，最多 64 条；校验矩形合法性和边界。
  • app_calib_find(x,y) 遍历矩形，返回第一个包含该坐标的区域条目；未命中/SD 不可用时返回 "UNKNOWN"/"未知区域"。
  • SD 不可用进入 "coordinates-only mode"（只给坐标不给名称）。

6.4 app_storage · 存储 app_storage.c / .h

  • SDMMC slot0，4 线，20 MHz；挂载 FATFS 到 /sdcard（挂载失败不自动格式化）；创建 frames/、snapshots/、logs/ 目录。
  • app_storage_logf()：带本地时间戳追加写 logs/app.log，用互斥锁保护并发。
  • app_storage_write_thermal_snapshot()：把整帧 160×120 写成 snapshots/frame_%06d.csv（首行注释含 frame_id/fpa_raw，矩阵按行逗号分隔）。
  • app_storage_self_test()：列目录 + 写读 1 KB 校验（0xA5）。

6.5 app_link · STM32 串口链路 app_link.c / .h

  • UART2，921600 baud；独立 task 负责队列发送 + 每秒一次心跳；sent_bytes 统计用于自检。
  • 三类消息：hot（热点）、hb（心跳）、st（阶段+进度）。JSON 转义处理引号/反斜杠，中文按 12 字符截断，UTF-8 安全。
  • 温度哨兵：NAN 温度经 (t > -272) 判断落空，输出 -273.0（合法 JSON，避免 nan 破坏对端解析）。

6.6 app_tts · 语音播报 app_tts.c / .h

  • UART1，9600 baud（注释注明 baud 待核实、模块须为 3.3 V 逻辑版本）；独立 task 从队列取文本。
  • 自带精简 UTF-8→GB2312 字库（约 67 个汉字），ASCII 直通，未收录字符跳过并告警；按 SYN6288 帧格式 FD len 01 00 + 文本 发送。
  • app_tts_speak_hotspot()：温度有效时播报"X元件发热，温度N度"（数字转中文：零~九十九）；无效时播报"X元件发热，温度未标定"。当前温度恒无效 → 恒播"未标定"。

6.7 app_cloud · 云端（默认关闭）app_cloud.c / .h

  • APP_WIFI_ENABLE=0 时所有函数直接返回 ESP_ERR_NOT_SUPPORTED，空 SSID/URL 不联网。
  • 启用后：NVS 初始化 → STA 模式连 WiFi → 事件组等待 GOT_IP / DISCONNECTED → HTTP POST JSON（application/json）或快照 CSV（text/csv），仅接受 2xx。

6.8 app_audio / app_vision / app_console 对应 .c / .h

  • app_audio：I2C0 挂 ES8311（7-bit 地址 0x18），I2S0 主机 24 kHz/16 bit/mono，MCLK/BCLK/WS/DOUT/DIN + PA GPIO；输入增益 30 dB；自检采样 1 s 算 peak/rms/有效位数。外置 INMP441 走 AUDIO_USE_EXTERNAL_I2S_MIC=0 关闭。
  • app_vision：LEDC 产生 20 MHz XCLK，I2C1 作 SCCB（地址 0x30）读 OV2640 的 PID(0x0A)/VER(0x0B)；只探测不采集，注释称 "plan B"。
  • app_console：UART0 REPL（提示符 s31>），注册 9 条命令（见 第 11 节）。

9.2 SYN6288 语音帧（UART1，9600）

帧结构 FD <len-hi> <len-lo> 01 00 <GB2312 文本>，其中 len = 文本字节数 + 1；文本由精简 UTF-8→GB2312 表转换而来。

13避坑清单

  • 别把 raw count 当摄氏度。raw_to_celsius() 恒为 NAN；看到 t=-273.0 是哨兵，不是真的零下 273 度测量值。
  • 别把 HOTSPOT_RAW_DELTA=1500 说成 "8℃"。源码注释明确否认这种换算，它是待标定的相对计数差。
  • esp32s31 是 preview 目标。idf.py 需带 --preview；且必须在已激活 IDF 的终端运行（沿用用户环境约定）。
  • 编译告警即错误（-Werror）。新增代码须消除所有 warning，否则编译失败。
  • SYN6288 只能接 3.3 V 逻辑。接 5 V RX 有损坏 S31 GPIO 的风险。
  • LINK TX 用 GPIO46，是 strapping 脚。若影响启动/ROM 日志，改 PINMAP_LINK_UART_TX 一处宏，并注意交叉接线+共地。
  • 热成像掉线会重启图像流。标定下载期间会暂停图像流；失败会 goto restart 恢复，勿假设下载期间仍有新帧。
  • 标定数据只存不算。PSRAM 里有标定数据不代表温度已可用，NUC 未实现。
  • SD 不挂载，标定查表就退化。CALIB 初始化依赖 SD；无 calib.csv 时只有坐标、无中文名。
  • 热点结果依赖连续两帧。单帧出现的瞬时热点会被跨帧确认过滤，控制台 hotspot_test 特意跑两次就是为此。
  • 云端默认不发数据。要联网必须同时置 APP_WIFI_ENABLE=1 并填 SSID/密码/URL。
  • 音频/摄像头是"预留能力"。不要把 cam_test 探测成功理解为已能拍照，也不要把 audio_test 当作业务语音链路。
